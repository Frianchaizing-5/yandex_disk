# Экспорт списка файлов с Яндекс.Диска (REST API)

В проекте несколько скриптов на Python 3 (только стандартная библиотека):

| Файл | Назначение |
|------|------------|
| `export_yandex_disk_index.py` | **Индекс:** каталог на Диске, имя файла, публичная ссылка (`public_url`). Файлы **не** скачиваются. |
| `publish_yandex_disk_tree.py` | **Публикация** всех файлов и папок внутри каталога + CSV с `public_url` (нужен `cloud_api:disk.write`). |
| `download_yandex_disk_folder.py` | **Скачивание** файлов из папки с сохранением структуры каталогов. |

Официальная документация API: [Доступ к API Яндекс.Диска](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart).

## Требования

- Python 3.
- OAuth-токен приложения Яндекс ID с правами **Яндекс.Диск REST API**: `cloud_api:disk.read` для индекса; для публикации — **`cloud_api:disk.write`**.

## Переменные и секреты

- Токен передаётся через **`YANDEX_DISK_TOKEN`** или аргумент **`--token`**.
- **Не коммитьте** токен и большие выгрузки с личными путями в git. При утечке токена отзовите доступ и выпустите новый в [oauth.yandex.ru](https://oauth.yandex.ru/).

## Экспорт индекса (CSV)

Рекурсивно обходит указанную папку и создаёт CSV с разделителем **`;`**, кодировка **UTF-8 с BOM** (удобно открывать в Excel).

Колонки:

- **`catalog`** — путь к **родительской папке** на Диске (например `disk:/ВКС записи/2024`).
- **`filename`** — имя файла.
- **`public_url`** — публичная («открытая») ссылка, если файл **опубликован**. Иначе поле пустое.

Пример (PowerShell):

```powershell
Set-Location "путь\к\проекту"
$env:YANDEX_DISK_TOKEN = "<токен>"
python export_yandex_disk_index.py --folder "ВКС записи" --out index.csv
```

Дополнительно:

- **`--full`** — для каждого файла выполняется отдельный запрос метаданных; иногда так надёжнее получить `public_url`, если в списке папки поле не пришло.

```powershell
python export_yandex_disk_index.py --folder "ВКС записи" --out index.csv --full
```

### Почему `public_url` может быть пустым

Публичная ссылка появляется только после **публикации** объекта (кнопка «Поделиться» в интерфейсе Диска или API `PUT /v1/disk/resources/publish`). Скрипт `export_yandex_disk_index.py` **не публикует** — только читает метаданные.

## Скрипт `publish_yandex_disk_tree.py` (публикация и ссылки)

Скрипт вызывает официальный метод **`PUT /v1/disk/resources/publish`** ([доступ к API](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart)) и затем читает метаданные, чтобы получить **`public_url`** для каждого обработанного объекта. Работа идёт через `https://cloud-api.yandex.net/v1`, без веб-клиента `disk.yandex.ru` (там при автоматизации часто встречается капча).

### Соответствие папки и URL в браузере

Фрагмент пути в ссылке вида `https://disk.yandex.ru/client/disk/<кодированное_имя>` — это **имя папки** в корне Диска. Пример: `%D1%82%D0%B5%D1%81%D1%82` — папка **`тест`**, в API путь **`disk:/тест`**. Вложенные каталоги задаются как в интерфейсе, например `--folder "Работа/тест"`.

### Права OAuth и токен

- Нужен scope **`cloud_api:disk.write`** (в интерфейсе приложения: что-то вроде «Запись в любом месте на Диске»).
- Токен, выданный **до** добавления права на запись, **не обновляется сам**: после смены прав приложения нужно **снова пройти авторизацию** и использовать **новый** токен. Иначе `publish` часто отвечает **HTTP 403 Forbidden**.
- Чтение списка файлов (`GET /disk/resources`) для полного обхода требует **`cloud_api:disk.read`**.

### Два режима: полный обход и только корень

| Режим | Команда | Результат |
|--------|---------|-----------|
| **Полный** | без `--root-only` | Рекурсивно для **каждого файла и каждой подпапки** вызывается публикация; в CSV у **каждой** строки своя `public_url` (ссылки вида `yadi.sk/i/...` для файлов и `yadi.sk/d/...` для папок). |
| **Только корень** | `--root-only` | Один вызов `publish` для **указанной папки**. В CSV **одна** строка. Вложенные файлы **не получают** отдельных `public_url` в API — если нужны ссылки на каждый файл, используйте **полный** режим. |

**Важно по безопасности:** после публикации объекты становятся доступны **по публичным ссылкам** (в рамках правил Диска). Убедитесь, что это допустимо для данных в каталоге.

### Порядок обхода (полный режим)

Сначала обрабатываются **вложенные** элементы (файлы и подпапки снизу вверх по дереву), в конце — **сама указанная корневая папка**. Имена на одном уровне сортируются по алфавиту (без учёта регистра). Это снижает риск гонок при последовательных запросах.

### Формат выходного CSV

- Разделитель **`;`**, кодировка **UTF-8 с BOM** (удобно для Excel).
- Колонки:
  - **`path`** — путь на Диске (`disk:/...`).
  - **`type`** — `file` или `dir`.
  - **`public_url`** — публичная ссылка после публикации (если API ещё не отдал поле, скрипт делает несколько повторных `GET` метаданных).

### Параметры командной строки

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `--token` | из `YANDEX_DISK_TOKEN` | OAuth-токен. |
| `--folder` | `тест` | Корневая папка для обхода или единственная папка при `--root-only`. |
| `--out` | `published.csv` | Путь к выходному CSV. |
| `--delay` | `0.15` | Пауза в секундах **между** обработкой объектов (снижает риск лимитов API). |
| `--poll` | `0.5` | Интервал опроса **асинхронной операции** (сек), если `publish` вернул ссылку с `/operations/`. |
| `--dry-run` | выкл. | Только вывести в stdout порядок путей (`type` и `path`), **без** `PUT publish` и без CSV. |
| `--root-only` | выкл. | Публиковать только `--folder`, без рекурсии по содержимому. |

### Поведение API внутри скрипта

1. **`PUT .../disk/resources/publish?path=...`** — публикация ресурса.
2. Если в ответе есть **`href`** с подстрокой **`/operations/`**, скрипт опрашивает этот URL, пока статус не станет **`success`** (или **таймаут** ~10 минут на одну операцию).
3. Ответ **HTTP 409** считается нормой: ресурс **уже опубликован**, повторный `publish` пропускается.
4. После успешного `publish` выполняется **`GET .../disk/resources?path=...`** с повторными попытками, чтобы стабильно прочитать **`public_url`**.

### Примеры (PowerShell)

Полная публикация дерева и сохранение всех ссылок в файл:

```powershell
Set-Location "путь\к\проекту"
$env:YANDEX_DISK_TOKEN = "<токен>"
python publish_yandex_disk_tree.py --folder "тест" --out published_all.csv
```

Только ссылка на саму папку (быстро, мало запросов):

```powershell
python publish_yandex_disk_tree.py --folder "тест" --root-only --out published_root.csv
```

Проверить порядок обхода без изменений на Диске:

```powershell
python publish_yandex_disk_tree.py --folder "тест" --dry-run
python publish_yandex_disk_tree.py --folder "тест" --root-only --dry-run
```

Увеличить паузу при лимитах или нестабильной сети:

```powershell
python publish_yandex_disk_tree.py --folder "ВКС записи" --out published.csv --delay 0.5
```

### Типичные проблемы

- **403 Forbidden** при `publish` — у токена нет права записи или токен выдан **до** включения `disk.write`; получите **новый** токен после авторизации.
- **«Файлы не опубликовались»** после `--root-only` — ожидаемо: у вложенных файлов не создаются отдельные публичные ссылки; запустите скрипт **без** `--root-only`.
- **Долго на больших каталогах** — полный режим делает несколько запросов на **каждый** файл и папку; используйте `--delay`, планируйте время или ограничьтесь `--root-only`, если достаточно одной ссылки на каталог.

### Связка с экспортом индекса

После публикации можно заново собрать таблицу через `export_yandex_disk_index.py` с `--full`, чтобы сверить **`public_url`** по файлам. Отмена публикации в API — отдельный метод **`unpublish`**; в этом проекте отдельного скрипта для `unpublish` нет.

## Скачивание файлов (опционально)

```powershell
$env:YANDEX_DISK_TOKEN = "<токен>"
python download_yandex_disk_folder.py --folder "ВКС записи" --out .\backup
```

Проверка без скачивания:

```powershell
python download_yandex_disk_folder.py --folder "ВКС записи" --out .\backup --dry-run
```

## Ограничения

- Обход через **официальный REST API**, не через веб-страницу `disk.yandex.ru` (там возможны капчи и нет стабильного «парсинга»).
- Для больших деревьев у `export_yandex_disk_index.py` режим **`--full`** делает на каждый файл дополнительный запрос — выполнение может занять много времени.
- Полный режим `publish_yandex_disk_tree.py` (без `--root-only`) на очень большом дереве даёт **много** запросов `publish` + `GET` на каждый объект; при необходимости увеличивайте **`--delay`**.
